## 1. 设计原则（工程约束）

1. **零硬编码颜色**：所有组件只允许引用 `--token`；浅/深主题仅体现在 `variable.less` 的两组令牌里。新增令牌必须同时给出两个主题的值。
2. **单一数据源**：页面状态一律来自后端接口；仅「会话列表 / 长期记忆」这类纯客户端偏好存 localStorage。
3. **AI 一律可降级**：任何 AI 接口失败都不允许白屏或 500 裸奔，必须有本地兜底或内联提示。
4. **改动可验证**：每次改完跑 `npm run build` + Playwright 全页面探测（桌面 1440×900 / 移动 390×844），失败不计入完成。

## 2. AI 助手页重构（对齐豆包）

### 2.1 布局（全幅三段式）
```
┌──────────────┬──────────────────────────────────┐
│ 会话栏 264px │  对话区（消息流）                  │
│ ────────────│                                  │
│ [+ 新建对话] │   …气泡…                          │
│ 会话 1   ✕  │                                  │
│ 会话 2   ✕  │   （空态：居中 Logo+标题+快捷问题） │
│ …           │                                  │
│ ────────────│                                  │
│ 🧠 记忆库(n) │  [📷][输入框………][➤]              │
└──────────────┴──────────────────────────────────┘
```
- 桌面：会话栏常驻；移动端：会话栏变为抽屉，由输入栏左侧「历史」按钮唤起。
- AI 路由走 `app-content--flush`（去掉容器 padding 与 max-width），实现真正的全幅。

### 2.2 多会话（前端持久化）
- 存储：`localStorage['jf_ai_sessions']` / `['jf_ai_active']`
- 结构：`[{ id, title, messages:[{role,content,image?,ts}], updatedAt }]`
- 能力：新建 / 切换 / 删除 / 自动命名（取首条提问前 12 字）/ 相对时间显示。

### 2.3 长期记忆（永久记忆）
- 存储：`localStorage['jf_ai_memories']`（用户可增删，上限 20 条、单条 120 字）。
- 生效方式：每次提问随请求带上 `memories`，后端拼入 system prompt：
  `…\n\n以下是用户的长期记忆（请结合这些信息回答）：\n- …`
- 后端改动：`ChatRequest.memories: Optional[List[str]]`、`AIService.chat(..., memories=None)`。

### 2.4 后续路线（本轮不做，留接口）
- **知识库（RAG）**：`kb_document` 表 + 分块 embedding + 向量检索（可用 SQLite-VSS 或 pgvector）；AI 页加「知识库」Tab。
- **流式输出**：`/ai/chat/stream`（SSE），逐字渲染。
- **服务端会话落库**：`ai_conversation` / `ai_message` 两表，跨设备同步。

## 3. 数据闭环（解决"页面全空"）

- `backend/seed_demo.py`：为 demo 用户生成 14 天数据
  - 体重：80.0 → 78.2kg 带噪声下降曲线
  - 饮食：每日 3 餐 × 2~3 项（内置 30+ 常见中国食物营养表）
  - 运动：随机 0~2 项/天（快走/慢跑/跳绳/力量）
  - 饮水：每日 1200~2400ml
- 运行方式：`python seed_demo.py --reset`（先清后灌）或 `python seed_demo.py`（仅补缺失天数）。
- 生产语义：真实用户数据不会被触碰（按 username 过滤）。
